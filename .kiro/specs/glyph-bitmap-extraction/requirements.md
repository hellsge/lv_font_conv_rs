# 需求文档

## 介绍

本文档定义了为 lv_font_conv 增加 glyph bitmap 提取功能的需求。该增强功能引入了一种新的导出格式，将 glyph bitmap 数组提取到独立的二进制文件中，用于嵌入式 flash 存储优化，同时保持 C 结构兼容性。

## 术语表

- **Glyph_Bitmap**: 包含每个字符字形渲染 bitmap 的像素数据数组
- **字体转换器**: lv_font_conv 系统，将矢量字体处理为 bitmap 格式
- **二进制提取器**: 负责将 glyph bitmap 数据分离到外部文件的组件
- **Flash 存储**: 嵌入式系统中存储二进制文件的非易失性存储器
- **宏引用**: 表示外部二进制数据内存地址的 C 预处理器宏
- **字体结构**: 包含字体元数据和 glyph 数据引用的 C 数据结构

## 需求

### 需求 1

**用户故事：** 作为嵌入式开发者，我希望将 glyph bitmap 数据提取到独立的二进制文件中，以便将字体数据存储在 flash 内存中并通过内存映射地址引用。

#### 验收标准

1. 当用户启用 bitmap 提取模式时，二进制提取器应创建包含所有 glyph bitmap 数据的独立二进制文件
2. 当创建二进制文件时，二进制提取器应使用 "{font_name}_glyph_bitmap.bin" 模式命名
3. 当生成 C 源文件时，字体转换器应将 glyph bitmap 数组数据替换为对外部二进制文件的宏引用
4. 当创建宏引用时，字体转换器应使用与二进制文件相同的基础名称作为宏标识符
5. 当启用 bitmap 提取时，字体转换器应保持原始字体结构，仅外部化 bitmap 数据

### 需求 2

**用户故事：** 作为嵌入式开发者，我希望 bitmap 提取功能能与现有的 LVGL C 代码生成配合工作，以便无缝集成到我当前的构建流程中。

#### 验收标准

1. 当 bitmap 提取与 LVGL C 输出格式结合时，字体转换器应生成有效的 LVGL 兼容 C 结构
2. 当生成带提取 bitmap 的 C 代码时，字体转换器应保留所有字体元数据、kerning 表和字符映射信息
3. 当创建二进制文件时，二进制提取器应使用与原始字体数据相同的字节序和压缩设置
4. 当 C 文件引用二进制数据时，字体转换器应包含指示外部二进制文件依赖的适当注释
5. 当处理启用提取的多个字体时，二进制提取器应为每个字体创建独立的二进制文件

### 需求 3

**用户故事：** 作为开发者，我希望有清晰的命令行选项来配置 bitmap 提取，以便在构建脚本中轻松启用此功能。

#### 验收标准

1. 当用户运行带帮助选项的 CLI 时，字体转换器应显示 bitmap 提取参数的文档
2. 当在不兼容的输出格式下启用 bitmap 提取时，字体转换器应显示适当的警告或错误消息
3. 当处理成功完成时，字体转换器应报告所有生成文件的名称和位置，包括二进制文件
4. 当启用 bitmap 提取时，字体转换器应验证输出格式支持外部二进制引用
5. 当指定输出目录时，二进制提取器应在与 C 源文件相同的目录中创建二进制文件

### 需求 4

**用户故事：** 作为开发者，我希望二进制提取能正确处理字体数据序列化，以便提取的二进制文件包含有效、可用的 glyph 数据。

#### 验收标准

1. 当序列化 glyph bitmap 数据时，二进制提取器应保留原始字体结构中使用的确切字节布局和位打包
2. 当创建二进制文件时，二进制提取器应以与目标系统相同的字节序写入数据
3. 当启用压缩时，二进制提取器应在写入文件前对二进制数据应用压缩
4. 当处理多个 glyph 时，二进制提取器应在 glyph 数据段之间保持适当的对齐和填充
5. 当创建二进制文件时，二进制提取器应确保文件大小与所有 glyph bitmap 数据的预期总大小匹配

### 需求 5

**用户故事：** 作为嵌入式开发者，我希望提取的二进制格式与内存映射 flash 访问兼容，以便直接使用 flash 地址作为数据指针。

#### 验收标准

1. 当生成宏引用时，字体转换器应创建可由用户定义为内存地址的宏
2. 当 C 结构引用 bitmap 数据时，字体转换器应使用与内存映射访问兼容的指针类型
3. 当创建二进制文件时，二进制提取器应确保适合直接内存访问的数据对齐
4. 当通过宏访问 glyph 数据时，字体转换器应保持与内联数组相同的数据布局
5. 当二进制文件加载到 flash 中时，字体转换器应确保生成的 C 代码可以无需修改地访问 glyph 数据
